# YouTube RAG Application

## Overview
The **YouTube RAG Application** (under the `ChatBoat/youtube_rag` module) is an intelligent, command-line-based conversational tool designed to interact with and query information from YouTube videos. 

## Problem It Solves
Watching long YouTube videos to find specific pieces of information can be time-consuming and inefficient. This application solves that problem by:
1. **Automating Transcript Extraction:** Automatically fetching the transcript of any YouTube video using just its Video ID.
2. **Context-Aware Information Retrieval:** Processing the transcript into semantic chunks and storing them in a local vector database.
3. **Interactive Q&A:** Allowing users to ask natural language questions about the video content and receiving precise, context-aware answers generated by a high-speed Large Language Model (LLM).

## Architecture & Workflow
The application implements a standard **Retrieval-Augmented Generation (RAG)** pipeline:
1. **Ingestion**: The user provides a YouTube Video ID. The `youtube_transcript_api` fetches the transcript.
2. **Chunking**: The transcript is split into smaller, overlapping text chunks using LangChain's `RecursiveCharacterTextSplitter`.
3. **Embedding & Storage**: The chunks are embedded using **Cohere** embeddings and stored locally in a **FAISS** vector database.
4. **Retrieval**: When the user asks a question, the application queries the FAISS database to find the top `k` most relevant transcript chunks.
5. **Generation**: The retrieved chunks and the user's question are sent to a **Groq** LLM (via LangChain), which generates an accurate response based on the video context.

## Detailed File Analysis

### 1. Core Application
- **`app.py`**
  The entry point of the application. It orchestrates the entire workflow: prompting the user for a Video ID, triggering the ingestion pipeline (transcript loading, chunking, and vector database creation), building the RAG chain, and running an interactive while-loop for continuous user Q&A.

### 2. Ingestion Module (`ingestion/`)
- **`transcript_loader.py`**
  Responsible for fetching YouTube transcripts. It uses the `youtube_transcript_api` to download subtitles (supporting English and Hindi fallbacks) and concatenates them into a single string.
- **`text_splitter.py`**
  Uses LangChain's `RecursiveCharacterTextSplitter` (with a chunk size of 1000 and overlap of 200) to break the massive transcript text into smaller, meaningful `Document` chunks that fit well within the LLM's context window.
- **`vector_store.py`**
  Handles the creation, saving, and loading of the local Vector Database. It uses `CohereEmbeddings` to convert the text chunks into vector embeddings and stores them in a `FAISS` index on the local filesystem.

### 3. Models Module (`models/`)
- **`llm.py`**
  Configures and initializes the LLM for the generation step. It uses `ChatGroq` for ultra-fast, low-latency inference, setting parameters like `temperature=0` (for deterministic, factual answers) and `max_tokens=1024`.

### 4. Retrieval Module (`retrieval/`)
- **`retriever.py`**
  Responsible for fetching relevant context. It loads the existing FAISS vector store and wraps it in a LangChain `VectorStoreRetriever`, defaulting to a standard `similarity` search to return the top 4 (`k=4`) most relevant chunks for a given query.

### 5. Chains Module (`chains/`)
- **`rag_chain.py`**
  Builds the final LCEL (LangChain Expression Language) pipeline. It runs the retriever and prompt in parallel, formats the retrieved documents, passes them to the LLM, and parses the output into a clean string format.

### 6. Prompts, Config, and Utils (`prompts/`, `config/`, `utils/`)
- **`prompts/prompt.py`**
  Contains the specific prompt templates (system/user instructions) that guide the Groq LLM to use the provided context to answer the user's query accurately.
- **`config/settings.py`**
  Centralized configuration file holding environment variables and static constants (e.g., `EMBED_MODEL`, `MODEL_NAME`, and `VECTOR_DB_PATH`).
- **`utils/logger.py`**
  Provides customized logging infrastructure used across all modules to track execution steps, debug issues, and record errors seamlessly.
